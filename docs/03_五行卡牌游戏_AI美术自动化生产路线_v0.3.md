# 五行卡牌游戏：AI 美术资源自动化生产路线 v0.3

## 1. 总目标

美术生产目标不是：

> AI 辅助人工制作。

而是：

> 尽量让美术成为自动资产流水线。

理想流程：

```text
游戏数据
→ 自动生成 Prompt
→ AI 自动生成资产
→ 自动视觉 QA
→ 自动重试
→ 自动裁切 / Resize / 命名
→ 自动写入 Godot 资产目录
→ Godot 自动导入
```

人工尽量只负责：

- 第一次确定风格
- 偶尔筛选候选
- 极少数失败资产人工干预

---

## 2. 人工工作最小化原则

尽量避免：

- 手工抠图
- 手工拆层
- 手工 Resize
- 手工命名
- 手工下载再搬文件
- 手工给每张卡绑图片
- 每张卡单独做框
- 每个技能单独做动画
- 每个角色制作传统逐帧动画
- 大量手工调色

核心思想：

> 数据是源头，图片和表现资源是生成物。

---

## 3. AI 与 Godot 的职责划分

### AI 负责

- 卡牌插画
- 玩家角色立绘
- 敌人立绘
- 战斗背景
- 区域概念
- 状态图标
- 五行图标候选
- 透明前景
- 部分特效纹理

### Godot 负责

- 卡框
- HP 条
- 能量显示
- 卡名
- 卡牌描述
- 数字
- 状态层数
- 按钮
- Glow
- Shader
- 粒子
- Tween
- 镜头震动
- 卡牌运动
- 战斗反馈

原则：

> AI 生成美术内容，Godot 生成游戏界面。

## 4. Style Master

第一阶段只做一次。

生成并确定少量风格参考图：

```text
style_master_character.png
style_master_card_art.png
style_master_battlefield.png
style_master_metal.png
style_master_wood.png
style_master_water.png
style_master_fire.png
style_master_earth.png
```

这些参考图统一确定：

- 人物比例
- 脸型
- 服装
- 东方幻想程度
- 材质
- 光照
- 饱和度
- 画面锐度
- 元素表现
- 卡牌插画构图

后续所有生成任务自动附带对应 Style Master。

---

## 5. 卡牌插画流水线

卡牌数据中增加：

```json
{
  "id": "fire_slash",
  "name": "烈焰斩",
  "element": "fire",
  "cost": 2,
  "base_damage": 20,
  "art_prompt": "黑发剑士挥出炽烈横向火焰剑气"
}
```

脚本自动执行：

```text
读取 cards.json
→ 读取 element
→ 读取 art_prompt
→ 自动拼接统一风格 Prompt
→ 自动加入元素 Style Master
→ 调用图像生成
→ 生成 1～N 个候选
→ Vision QA
→ 失败则重试
→ 成功则保存
```

输出：

```text
res://assets/cards/generated/fire_slash.webp
```

---

## 6. 卡牌插画不包含 UI

AI 只生成纯插画。

禁止生成：

- 卡名
- 数字
- 费用
- 描述
- 卡框
- 元素图标
- 品质边框

这些全部由 Godot 实时绘制。

这样改数值完全不需要重新生成图片。

---

## 7. 卡框只做一套基础模板

推荐：

```text
CardFrame
├── Background
├── ElementBorder
├── ArtworkMask
├── CostBadge
├── NameLabel
├── DescriptionLabel
└── ElementIcon
```

根据：

```text
card.element
```

自动设置：

- 边框主题
- Glow
- 元素图标
- 小装饰
- 粒子

不需要人工制作五张完全独立卡框。

---

## 8. 角色资产

MVP 每个角色只做：

- 1 张透明背景战斗立绘
- 头像自动裁切

不做：

- 多姿势
- 多表情
- 逐帧动画
- 手工骨骼拆件

立绘生成要求：

- 透明背景
- 半身或大半身
- 构图稳定
- 主体轮廓清楚
- 武器不要超出太远
- 风格严格参考 Style Master

---

## 9. 角色动态全部在 Godot 中完成

单张 PNG 通过：

- 呼吸缩放
- 上下漂浮
- 轻微旋转
- 攻击前冲
- 受击震动
- 闪白
- 元素 Aura
- Shader 扭曲

制造“活着”的观感。

不要求传统角色动画。

---

## 10. 战斗背景

每个区域只生成：

1 张主背景。

建议：

- 16:9 或略宽
- 主体不要太靠边
- 中央预留战斗信息空间
- 不包含 UI
- 不包含文字

Godot 叠加：

- 雾
- 火星
- 落叶
- 雨
- 水光
- 漂浮粒子
- 色彩变化

形成动态场景。

---

## 11. 不人工拆背景层

MVP 不要求手工把背景拆成：

```text
天空
山
建筑
前景
```

如果需要纵深：

额外自动生成少量透明前景：

```text
foreground_rocks.png
foreground_branches.png
foreground_fog.png
```

再由 Godot 做轻微视差即可。

---

## 12. 五行图标与状态图标

统一批量生成。

要求：

- 正方形
- 单主体
- 无文字
- 透明背景
- 高对比
- 统一线条风格
- 在 32～64 px 下仍然可识别

例如：

```text
metal.png
wood.png
water.png
fire.png
earth.png

burn.png
shield.png
vulnerable.png
regen.png
element_lock.png
fatigue.png
draw.png
```

## 14. 特效参数化

卡牌数据可以直接附带：

```json
{
  "fx_id": "fire_slash",
  "fx_scale": 1.2,
  "fx_speed": 1.0,
  "fx_intensity": 1.1
}
```

Godot：

```gdscript
play_fx(
    card.fx_id,
    card.fx_scale,
    card.fx_speed,
    card.fx_intensity
)
```

几十张卡可以复用同一套表现。

## 15. 自动 QA

生成资产不能直接入库。

使用视觉模型自动检查。

### 卡牌插画检查

- 是否含文字
- 是否符合竖版构图
- 主体是否清晰
- 是否与元素主题一致
- 是否偏离 Style Master
- 是否存在明显人体错误
- 武器是否严重畸形
- 是否大面积过暗 / 过曝

### 角色检查

- 背景是否透明
- 人物是否被裁掉
- 身体范围是否符合要求
- 角色身份是否稳定
- 服装是否漂移
- 武器是否严重错误

### 图标检查

- 是否单主体
- 是否无文字
- 是否透明背景
- 是否小尺寸可识别

失败：

```text
自动重试
```

成功：

```text
进入后处理
```

---

## 16. 自动后处理

脚本自动完成：

- 裁切
- Resize
- 转 WebP / PNG
- 保留透明通道
- 文件重命名
- 路径整理
- 元数据记录

例如：

```text
output_193847.png
```

自动变为：

```text
fire_slash.webp
```

## 17. Godot 资源路径约定

### 卡牌

```text
res://assets/cards/generated/{card_id}.webp
```

### 角色

```text
res://assets/characters/{character_id}.webp
```

### 背景

```text
res://assets/backgrounds/{area_id}.webp
```

### 图标

```text
res://assets/icons/{icon_id}.png
```

游戏代码按 ID 自动加载。

不允许依赖人工逐项绑定。

## 20. 最省人工的表现组合

推荐：

```text
高质量 AI 静态插画
+
程序化 UI
+
Godot Tween
+
Shader
+
粒子
+
镜头震动
+
复用型元素 FX
```

避免：

```text
完整 3D
+
骨骼角色动画
+
逐帧动画
+
大量人工修图
+
每张牌单独做特效
```

## 21. 更进一步的自动化

未来可追加：

### 自动生成卡牌插画

新增 card JSON 后自动跑。

### 自动生成敌人视觉

Enemy JSON：

```json
{
  "id": "fire_monk",
  "main_element": "fire",
  "visual_prompt": "..."
}
```

自动生成：

- 战斗立绘
- 头像

### 自动生成卡牌描述

根据 Effect 自动生成自然语言描述。

### 自动截图 QA

Godot 自动打开卡牌测试场景并截图。

视觉模型检查：

- 文字是否溢出
- 图片是否缺失
- 卡面是否遮挡
- 数值是否异常
- 元素图标是否正确

### 自动构建测试包

最终流水线可扩展为：

```text
数据更新
→ 美术生成
→ QA
→ Godot 导入
→ 单元测试
→ 自动截图
→ UI QA
→ 构建试玩版本
```

---

## 22. 最终原则

> 新增内容时，人主要填写数据；图片、文件、UI 绑定和大部分视觉表现尽量自动完成。

如果新增一张卡还需要手动经历十几个步骤，就说明管线还没有自动化到位。
